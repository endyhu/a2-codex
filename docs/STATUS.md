## Stats page (`src/pages/stats.astro`), finished
- **Layout:** left, a wheel like the in-game Stat Info window (6 primary stats inside 10 Daevanion stats, 5 per side in the game's order), fixed to the screen and centred on desktop. Right, "Most important stats": 15 ranked rows with the official description, a plain-language note, which wheel stats raise it (coloured chips) and where to get it (GEAR / OTHER tags). Stacks on narrow screens.
- **Interaction:** hovering or tapping a wheel stat shows a tooltip and lights up the rows it raises; hovering a row lights up its wheel stats (gradient when two). Tag groups longer than four collapse behind a "+N" popup (hover/focus, or tap to pin, tap elsewhere to close).
- **Sources:** descriptions from aion2data.com / metabot.gg (Global client data); order and notes from the Aion 2 Bible (community guide). "Get it from" tags are generated: run `mise exec -- node scripts/global-sources.mjs` to rebuild `src/data/stat-sources.json` from metabot.gg's Global client data (re-run after each patch). Dashed tags (Genus Insight, Wings) are community or unconfirmed. See `docs/data-sources.md` for the source policy.
- **External links** open in a new tab everywhere: `markExternalLinks` in `Base.astro` sets `target="_blank"` and `rel="noopener noreferrer"` on every non-same-origin `a[href^="http"]` on each page load, so new pages need nothing extra.
- **Tags link to pages** once the matching nav page is `ready` (map in `TAG_PAGE`, stats.astro).
- **Themes:** light uses the same styling as dark with colours retuned for white; do not restyle light separately. The theme toggle and the GitHub repo link are icon buttons in `.side-tools` at the bottom of the sidebar (`Base.astro`; the GitHub mark is an inline SVG, lucide has none).
- **Known gaps:** icons are generic Lucide stand-ins (real emblems need the owner's own screenshots, no chat/account details visible). Attack Bonus has no client-data source. Wings tag is unconfirmed on Global. Only the top two gear tiers are read by the sources script.

## Daevanion Optimizer (`src/pages/daevanion/index.astro`), finished
- **What it is:** a tool, not a cheatsheet. Inputs: class, PvE/PvP focus, which standard boards (Nezekan, Zikel, Vaizel, Triniel) and the crystal pool for each of the three pools (a pool of 0 skips Ariel/Azphel), an ordered "Must-have skills" list. Output: the provably best connected route per board, recomputed live (120ms debounce, no Optimize button); about 0.05 to 0.4s. Status text shows "Optimal · time". Settings persist in `localStorage` (`a2codex-daevanion-v1`).
- **Algorithm:** `src/scripts/daevanion-solver.ts`, ported unchanged from the standalone optimizer (frontier DP per board, knapsack across boards sharing a pool, lexicographic tier scoring, `verify()` on every result). Checked against the old page: identical stat totals for Gladiator PvE 400, Cleric PvP with all six boards, Ranger PvE with all six boards. `weigh()` builds the tiers: must-have actives (in order) > orange rewards > must-have passives > Attack Bonus > Critical Hit > other passives > other actives > other stats (PvE: one soft-weighted tier; PvP: one strict tier each). Old tool's three skill lists (key actives, key passives, extra actives) became one list that is split by skill type, so key passives still follow orange rewards. Cross-checked with the Aion 2 Bible's Daevanion chapter (key actives, then orange, Attack Bonus tiles valuable, Multi-hit Resist and Critical Damage Tolerance oranges worthless in PvE, Ariel orange = PvE Damage Boost/Tolerance): all match. The Bible also lists Marchutan and Yustiel individual boards that are not in our data (unknown if on Global); it calls Azphel PvP, skip. Azphel and Ariel keep their fixed orders (orange first). Stat orders are fixed, no editing UI (owner chose skills only + mode).
- **Data:** `src/data/daevanion.json` (boards, stat labels, `pct`, `ref`, skill active/passive, skill icon ids), extracted from questlog.gg's AION 2 data; there is no extractor in the repo, refresh by hand on patches (format: `{classes:{Class:[{n,p,nodes}]}, lab, pct, ref, skc, icons}`; node = `[row, col, cost, key, value, ...]`, skill keys `s:<Name>`; pools `c` Daevanion, `q` Conquest (Ariel), `a` Battle (Azphel); `pct` stats are stored x100). Brawler is not on Global and is left out. Icons: class emblems in `src/assets/daevanion/class` (rendered with Astro `Image`, resized to 72px at build), skill icons in `public/daevanion/skill` (owner approved copying them).
- **Layout:** Setup panel left (440px), Route right (board tabs, 15x15 board, stat totals, skill levels); stacks under 1100px. Setup: class buttons, Focus cards (PvE castle / PvP swords), board cards above the crystal budgets (budgets saved per class, old single-set saves migrate to the open class), Must-have skills as two lists (Active blue, Passive green; the list order only matters within a type, because the scoring puts actives before orange rewards and passives after), then the Scoring order. Board: plain stat tiles are the panel colour with a faint tint and a coloured Lucide stat icon (offense red, accuracy/crit purple, defense/HP teal, other slate; the point cost is a small corner digit), skills fill the tile with art and a blue/green outline, orange rewards are gold, not-taken tiles are dimmed, white lines join taken neighbours. Skill levels are listed must-haves first (as in Setup), then by levels gained, then A to Z. Hover or tap a tile for the exact effect.
- **Images:** class emblems and the Arcana art go through Astro `Image` (`src/assets`); the script-made skill icons choose eager or lazy by where they sit on screen (`hydrate()`), which keeps the Astro dev-toolbar loading audit quiet.
- **Not done / open:** crystal pool names are the data's point types, not checked in game. Not checked on a real phone (touch tooltips). Stat order/weights are the old tool's defaults, not re-validated for Global. The nav item has no sub-sections, so no section glow.

## Market (`src/pages/market/index.astro`), finished
- **What it is:** a tool. Filters (region, faction, item type, minimum listings per server, saved in `localStorage` `a2codex-market-v1`) and a searchable table of items listed on two or more of the chosen servers: cheapest server and price, most expensive server and price, gap in % and Kinah. Sortable headers (default A to Z); click a row for every server's price, listings and % above the cheapest. Compares within one region at a time (default Europe); Elyos and Asmodian servers can be compared together or separately. Shows 100 rows, "Show more" adds 100.
- **Data:** `scripts/market-snapshot.mjs` (`mise exec -- node scripts/market-snapshot.mjs`, about 1 minute) writes `public/market.json` (about 770 KB, loaded client-side by the page). It is committed as a fallback; `deploy.yml` re-fetches on every push (`continue-on-error`) and `.github/workflows/market-refresh.yml` rebuilds and deploys every 6 hours with a fresh snapshot. The schedule commits nothing. Source and rules: `docs/data-sources.md` > Market page.
- **Not done / open:** defaults (all servers, all items, 6 h refresh) were chosen without asking the owner. Outlier single listings make the Gap sort noisy (min listings 3 helps). No price history, no per-item deep link. The scheduled workflow is untested until pushed. Phone layout checked by DOM measurements only (no overflow at 360), not by eye; the preview pane was too small to judge 1920/3440 visually (widths measured: main 1500px, no overflow).

## Page switches (Astro `ClientRouter` in `Base.astro`)
- Full page loads showed a blank frame in Vivaldi/Chromium on every click, so the site uses Astro's client-side router: it fetches the next page and swaps it in, no reload. The sidebar (phone: top bar) has its own `view-transition-name` and stays still; the content crossfades in 0.12s and the browser's own 250ms page-group animation is off (off entirely for reduced motion); a switch takes about 160ms on the built site. The dev server renders Stats and Gear on each request (about 300ms), so judge speed with the `astro-preview` launch config (built site, port 4322) after `npm run build`. `scrollbar-gutter: stable` keeps the layout from shifting sideways between short and long pages.
- **Page scripts** run inside `document.addEventListener('astro:page-load', ...)`, return early when their page's element is missing, and pass `{ signal }` to every window/document listener (aborted on `astro:before-swap`). New pages with scripts must follow the same pattern. Base's own script runs once and uses delegated clicks.
- **Theme:** the incoming page's `<html>` says dark, so `astro:after-swap` re-applies the saved theme; the `color-scheme` meta follows the theme.
- **Section links on the current page** get `data-astro-reload` on each page load so the browser does the smooth scroll (the router would jump instantly); a `hashchange` handler copies router state onto that history entry so Back still swaps pages correctly.
- **Testing:** the router waits for a painted frame, so it stalls while the preview pane is hidden (call `show_pane` first). Use real clicks (`computer`) to judge transitions. `Transition was skipped` console errors only came from hidden-pane or scripted tests.
- **Update banner:** `astro.config.mjs` bakes a build id into the pages (`__BUILD_ID__`) and writes `dist/version.json`. Base checks it on tab focus and every 5 minutes (`no-store`); when it differs, the persisted `#update` bar (green, top middle; "New version available" with a round refresh-icon button that spins on hover) appears. Not shown in dev (no version file). Not yet checked: that the bar stays visible across a router page switch (the hidden preview pane stalls switches; use a real click with the pane shown). Clicking the arrows sets `sessionStorage.updating`; from then on each page's first router load is preceded by a `cache: 'reload'` fetch (`astro:before-preparation`), because GitHub Pages' ~10 min cache served old-build pages whose old script re-showed the bar. Fix is from code reading; not reproduced on a live deploy.

## How to test the layout (the browser pane is narrow)
- Desktop and ultrawide: load the page in an iframe sized 1280, 1920 or 3440 wide and scale it down with CSS transform, then measure with JS. Check phone width at about 360.
- Call `show_pane` (preview) before taking screenshots, or they time out.
- Animations barely run in the hidden preview pane. To judge a glow, add the `flash` class by script and freeze it with a style override (`animation: none; opacity: 1` for the step strips), then compare frozen frames; check sizes and edges with `getComputedStyle(el, '::after')`.
- The dev server can serve stale CSS or layout code after many edits: restart it (`preview_stop`, `preview_start`) or hard refresh before judging a change.
